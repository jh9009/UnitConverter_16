## §1. 실제 인터뷰 결론 (라이브 세션)

### 1.1 표면 문제 (잘못된 정의)

> "길이 단위 변환 **CLI/프로그램을 만들면** 임상 데이터 변환이 편해질 것이다."

솔루션(프로그램·CLI)을 먼저 가정하면, 실제 불편(에러 없는 중단, 수동 디버깅, 재작업)이 가려질 수 있다.

### 1.2 진짜 문제 (한 문장)

입력 형식 오타 하나로 변환이 **에러 없이 중단**되면, 어디가 틀렸는지 알 수 없어 **30분 넘는 수동 추적**(터미널·소스·엑셀)과 **처음부터 재작업**이 반복되고, 그 비용을 줄이려 사용자가 **메모장 검사·한 줄씩 복붙** 같은 추가 루틴까지 스스로 부담한다.

### 1.3 Mom Test 증거 (페르소나 답변 인용)

1. "터미널 스크립트에 `feet:5.8`처럼 텍스트를 **수동으로 계속 입력**하고 있었고, 오타 한 번에 스크립트가 **에러 메시지 없이** 뻗었다."
2. "원인 찾느라 **30분 넘게** 허비했고, 터미널 스크롤 확인 → 소스 `if-else` 눈으로 훑기 → 엑셀에서 **어디까지 변환됐는지** 찾은 뒤 **처음부터 다시** 돌렸다."
3. "그 다음부터는 **메모장에 값을 먼저 적고**, 콜론·공백을 **눈으로 검사한 뒤** 터미널에 **한 줄씩 복사·붙여넣기**한다."

### 1.4 인터뷰 요약

| 항목 | 내용 |
|------|------|
| **마지막 행동** | 임상 데이터 변환 중, 터미널 스크립트에 `단위:값` 형식(`feet:5.8` 등)을 손으로 반복 입력 |
| **핵심 불편** | 오타 1회 → 스크립트 묵살 종료, 에러 메시지·줄 번호 없음 → 원인 특정 불가 |
| **비용** | 원인 찾기 **30분 이상** + **전체 재입력·재실행** |
| **사고 이후 변화** | 메모장 선작성 → 콜론·공백 눈 검사 → 한 줄씩 복붙 (작업 단계 증가) |

### 1.5 인터뷰 규칙 준수 여부

| 규칙 | 준수 |
|------|------|
| 한 번에 질문 1개 | ✅ |
| 솔루션 제안 금지 (CLI, 리팩토링, TDD 등) | ✅ |
| 과거·구체·사실 중심 질문 | ✅ |
| 모호 시 추궁 1개 | ✅ |

## §2. Mom Test 질문 10개 (설계 참고)

페르소나 기준으로 카테고리별 2문항(✅ 준수 5 / ❌ 위반 5).

### 2.1 마지막으로 스크립트가 뻗었을 때 (과거)

| # | 질문 | 판정 |
|---|------|------|
| Q1 | 지난번에 변환 스크립트가 갑자기 멈췄을 때, 그 직전에 **무슨 일을 하고 있었어요?** 기억나는 대로 순서대로 말해줄 수 있어요? | ✅ |
| Q2 | 스크립트가 뻗을 때 **에러 메시지를 더 자세히 보여주는 기능**이 있으면 도움이 될 것 같아요? | ❌ |

**Q2 위반 이유:** 미래·솔루션 가설 질문 → 실제 불편·행동이 아닌 "좋아 보이는 기능"에 답하게 됨.  
**✅ 고친 버전:** 지난번에 스크립트가 뻗었을 때, 화면에 **뭐가 보였어요?** 에러 문구가 있었는지 없었는지 기억나요?

### 2.2 에러 원인 파악 및 복구 비용 (시간/행동)

| # | 질문 | 판정 |
|---|------|------|
| Q3 | 그때 원인 찾느라 **대략 몇 분** 걸렸어요? 그 시간 동안 **실제로 뭘 해봤어요?** | ✅ |
| Q4 | 에러 나면 **30분 안에** 잡을 수 있게 하려면 **어떤 도구**가 필요할까요? | ❌ |

**Q4 위반 이유:** 목표 시간·도구 선호 설계 질문 → 과거에 실제로 쓴 방법·낭비한 시간이 드러나지 않음.  
**✅ 고친 버전:** 원인을 못 찾아서 **포기하거나 처음부터 다시** 한 적이 있어요? 있다면 그때 **뭘 다시 했어요?**

### 2.3 임시방편(메모장 복붙 등)을 처음 시작한 순간

| # | 질문 | 판정 |
|---|------|------|
| Q5 | 터미널에 바로 치지 않고 **메모장에 적었다가 복붙**하기 시작한 건 **언제쯤**이에요? 그때 **뭔 일이 있었어요?** | ✅ |
| Q6 | 앞으로도 **메모장 검사 루틴**을 계속 쓸 것 같아요? | ❌ |

**Q6 위반 이유:** "~할 것 같아요"는 의견·예측 → 루틴을 **언제·왜 시작했는지** 사실이 안 나옴.  
**✅ 고친 버전:** 메모장에 먼저 적기 시작한 **그날**, 스크립트 쓰는 방식에서 **뭐가 달라졌어요?**

### 2.4 똑같은 에러가 다시 터졌을 때의 반응

| # | 질문 | 판정 |
|---|------|------|
| Q7 | 비슷하게 입력 잘못해서 스크립트가 또 멈춘 적 **있어요?** 가장 최근이 **언제**였고, 그때 **뭐부터 했어요?** | ✅ |
| Q8 | 같은 오류가 반복되면 **자동 검증**을 넣는 게 맞다고 생각해요? | ❌ |

**Q8 위반 이유:** 아키텍처·기능 동의 질문 → 재발 시 **실제 반응**이 안 나옴.  
**✅ 고친 버전:** 똑같은 식으로 또 뻗었을 때, **그때도 처음부터 다시** 돌렸어요, 아니면 **그때는 달리** 대응했어요?

### 2.5 동료나 다른 사람이 만든 변환 코드를 쓸 때의 경험

| # | 질문 | 판정 |
|---|------|------|
| Q9 | 본인 말고 **다른 사람이 만든** 변환 스크립트를 써본 적 있어요? **가장 최근**에 그걸 쓸 때, **어디서 막혔거나 헷갈렸어요?** | ✅ |
| Q10 | 동료 코드보다 **직접 만든 CLI**가 나을 것 같아요? | ❌ |

**Q10 위반 이유:** 비교·솔루션 선호 질문 → 동료 코드 쓸 때의 **구체적 불편**이 수집되지 않음.  
**✅ 고친 버전:** 동료가 만든 변환 코드를 쓸 때, **입력 형식**이나 **에러가 났을 때** 어떻게 됐는지 **한 번** 기억나는 사례 말해줄 수 있어요?

## §3. 역할 분리 시뮬레이션 결론

> **⚠️ 가상 시뮬레이션** — §1 실제 인터뷰와 **별개**의 가상 3턴 세션. 임상 데이터·메모장 복붙 사례를 인용하지 않음.

**가상 페르소나:** 연구실/회사에서 단위 변환 스크립트를 돌리다가, 오타(공백·콜론 누락 등)로 전체 작업을 날린 적 있는 작업자

### 3.1 표면 문제 (잘못된 정의)

> "길이 단위 변환 **스크립트/CLI를 새로 만들거나 고치면**, 연구실 보고서용 데이터 변환이 편해질 것이다."

### 3.2 진짜 문제 (한 문장)

`단위:값` 형식 입력에서 **콜론·공백 같은 사소한 오타**가 나면 스크립트가 **조용히 끊기고**, 어디까지 처리됐는지 **CSV·터미널을 수동으로 대조**해야 해서 **40분 가까운 재작업**이 생기며, 그 비용을 피하려 사용자가 **엑셀에서 문자열을 미리 조립·10줄마다 행 수 확인** 같은 추가 루틴을 스스로 붙인다.

### 3.3 가상 인터뷰 증거 3줄

1. "31번째 줄에서 `meter 9.1`처럼 **콜론을 빼먹고** 붙여넣었는데, 스크립트가 바로 끊겼고 화면에는 **`Done.`만** 찍혔다."
2. "출력 CSV는 **30행까지만** 있었고, 원인 찾고 **31번부터 다시 입력**하는 데 **40분 가까이** 걸렸다."
3. "그 다음 주 월요일부터 엑셀에 **`meter:`를 미리 붙인 문자열만** 복사하고, **10줄마다 CSV 행 수**를 세기 시작했다."

### 3.4 시뮬레이션 3턴 요약

| Turn | 질문 초점 | 핵심 답변 |
|------|-----------|-----------|
| 1 | 최근 입력 오류로 작업 꼬인 때 | 3월 둘째 주, 신소재 시편 48개, 31번째 줄 콜론 누락, `Done.`만 출력 |
| 2 | 끊긴 뒤 복구 행동 | CSV 30행 확인 → 터미널 대조 → 31번부터 재입력, **~40분** |
| 3 | 사고 이후 달라진 루틴 | 다음 주 월요일부터 엑셀에 `meter:` 미리 붙임, 10줄마다 CSV 행 수 확인 |

## §4. 통합 해석 및 다음 단계

### 4.1 §1(실제) vs §3(가상) 공통 신호

| 신호 | §1 실제 | §3 가상 |
|------|---------|---------|
| 입력 오타 1회로 중단 | ✅ 에러 메시지 없음 | ✅ `Done.`만 출력 |
| 원인 특정 불가 | ✅ 터미널·소스·엑셀 수동 추적 | ✅ CSV 행 수·터미널 대조 |
| 복구 비용 | 30분+ | ~40분 |
| 자발적 우회 루틴 | 메모장 선작성·복붙 | 엑셀 문자열 조립·10줄마다 행 수 확인 |
| 문제 해결 여부 | ❌ 단계만 증가 | ❌ 단계만 증가 |

두 세션 모두 **같은 진짜 문제**를 가리킨다: 입력 검증·에러 피드백·진행 지점 가시성 부재.

### 4.2 다음 단계 시사점 (구현 방향 참고용)

아래는 인터뷰·시뮬레이션 공통 결론에서 도출된 요구 힌트이다.

- **입력 값 검증** — 잘못된 형식·없는 단위·음수 등에 대해 명확한 에러 메시지
- **실패 시 재현 가능성** — 어떤 입력이 문제인지, 어디서 멈췄는지 알 수 있어야 함
- **조용한 종료 방지** — 오류 시 `Done.` 등 성공처럼 보이는 출력 금지
- **반복 수동 입력 부담 완화** — 배치 입력·중간 저장·재시작 지점 복구 (구체 설계는 STEP 2 이후)
