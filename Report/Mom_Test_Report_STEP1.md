# UnitConverter_16 — Mom Test 인터뷰 보고서 (STEP 1)

**일자:** 2026-06-05  
**방법:** Rob Fitzpatrick Mom Test 스타일 인터뷰  
**페르소나:** 다양한 길이 단위(미터, 피트, 야드 등) 변환 코드를 유지보수하거나, 반복적으로 수동 변환 작업을 하며 에러를 겪는 작업자

---

## 1. 표면 문제 (잘못된 정의)

> "길이 단위 변환 **CLI/프로그램을 만들면** 임상 데이터 변환이 편해질 것이다."

솔루션(프로그램·CLI)을 먼저 가정하면, 실제 불편(에러 없는 중단, 수동 디버깅, 재작업)이 가려질 수 있다.

---

## 2. 진짜 문제 (한 문장)

입력 형식 오타 하나로 변환이 **에러 없이 중단**되면, 어디가 틀렸는지 알 수 없어 **30분 넘는 수동 추적**(터미널·소스·엑셀)과 **처음부터 재작업**이 반복되고, 그 비용을 줄이려 사용자가 **메모장 검사·한 줄씩 복붙** 같은 추가 루틴까지 스스로 부담한다.

---

## 3. Mom Test 증거 (페르소나 답변 인용)

1. "터미널 스크립트에 `feet:5.8`처럼 텍스트를 **수동으로 계속 입력**하고 있었고, 오타 한 번에 스크립트가 **에러 메시지 없이** 뻗었다."
2. "원인 찾느라 **30분 넘게** 허비했고, 터미널 스크롤 확인 → 소스 `if-else` 눈으로 훑기 → 엑셀에서 **어디까지 변환됐는지** 찾은 뒤 **처음부터 다시** 돌렸다."
3. "그 다음부터는 **메모장에 값을 먼저 적고**, 콜론·공백을 **눈으로 검사한 뒤** 터미널에 **한 줄씩 복사·붙여넣기**한다."

---

## 4. 인터뷰 요약

### 마지막 행동
- 임상 데이터 변환 중, 터미널 스크립트에 `단위:값` 형식(`feet:5.8` 등)을 손으로 반복 입력

### 핵심 불편
- 오타 1회 → 스크립트 묵살 종료, 에러 메시지·줄 번호 없음 → 원인 특정 불가

### 비용
- 원인 찾기 **30분 이상** (터미널 확인 → 소스 훑기 → 강제 종료 → 엑셀에서 진행 지점 확인)
- 결국 **전체 입력·재실행** 필요

### 사고 이후 변화 (자발적 우회 루틴)
- 터미널 직접 입력 대신 **메모장 선작성 → 콜론·공백 눈 검사 → 한 줄씩 복붙**
- 문제가 해결된 것이 아니라 **작업 단계가 늘어난** 형태로 불편이 이전됨

### Mom Test 해석
- 사용자가 **추가 단계를 스스로 부담** → 문제가 여전히 "있음"을 강하게 시사
- 실패 시 **자동 디버깅 경로 부재** → 수동 디버깅 루틴(터미널·소스·엑셀)에 의존

## 5. 인터뷰 규칙 준수 여부

| 규칙 | 준수 |
|------|------|
| 한 번에 질문 1개 | ✅ |
| 솔루션 제안 금지 (CLI, 리팩토링, TDD 등) | ✅ |
| 과거·구체·사실 중심 질문 | ✅ |
| 모호 시 추궁 1개 | ✅ |
| 솔루션 언급 시 "그건 나중" 리다이렉트 | 해당 없음 (페르소나가 솔루션 제안 없음) |

## 6. 다음 단계 시사점 (구현 방향 참고용)

아래는 인터뷰 결론이 아닌, **진짜 문제**에서 도출된 요구 힌트이다.

- **입력 값 검증** — 잘못된 형식·없는 단위·음수 등에 대해 명확한 에러 메시지
- **실패 시 재현 가능성** — 어떤 입력이 문제인지, 어디서 멈췄는지 알 수 있어야 함
- **반복 수동 입력 부담 완화** — 배치 입력·재시작 지점 복구 등 (구체 설계는 STEP 2 이후)
