## §1. Mom Test 요약

### 페르소나

길이 단위 변환(미터, 피트, 야드) 스크립트를 반복적으로 수동 조작하다가, 입력 오류(공백·콜론 누락 등)로 프로그램이 뻗어 시간을 낭비한 작업자.

### 표면 문제 (잘못된 정의)

> "길이 단위 변환 CLI/프로그램을 만들면 임상 데이터 변환이 편해질 것이다."

### 진짜 문제 (한 문장)

입력 형식 오타 하나로 변환이 **에러 없이 중단**되면, 어디가 틀렸는지 알 수 없어 **30분 넘는 수동 추적**과 **처음부터 재작업**이 반복되고, 그 비용을 줄이려 사용자가 **메모장 검사·한 줄씩 복붙** 같은 추가 루틴까지 스스로 부담한다.

### Mom Test 증거 3줄

1. `feet:5.8` 수동 반복 입력 중 오타 → **에러 메시지 없이** 뻗음
2. 원인 찾기 **30분+** (터미널 → 소스 if-else → 엑셀 → 처음부터 재실행)
3. 이후 **메모장 선작성 → 콜론·공백 검사 → 한 줄씩 복붙**

### 부가 산출물 (STEP 1)

- Mom Test 질문 10개 (✅ 5 / ❌ 5, 카테고리별 준수·위반 분석)
- 역할 분리 가상 시뮬레이션 3턴 (신소재 시편 48개, CSV 30행, ~40분 재작업 — §1 실제와 별개)

### §1·시뮬레이션 공통 신호

입력 검증·에러 피드백·진행 지점 가시성 부재. 우회 루틴 도입 = 문제 미해결.

## §2. STEP 1 워크북 (PRD 초안)

### 주제 (두 줄 분리)

**진짜 문제:** 입력 오타(콜론 누락, 공백, 잘못된 단위) 하나로 변환이 에러 없이 끊기면, 어디가 틀렸는지 알 수 없어 30분 넘는 수동 추적·처음부터 재작업과 메모장 검사·한 줄씩 복붙 같은 우회 루틴이 반복된다.

**구현 목표:** 그 조용한 실패를 없애기 위해, 잘못된 입력마다 즉시 무엇이 틀렸는지 알려주는 검증과 정확한 길이 단위 변환을 구현한다.

### R-G-I-O

| 항목 | 내용 |
|------|------|
| Role | 길이 단위 변환 스크립트를 리팩토링·검증하는 개발자 |
| Goal | `meter:2.5` 정확 변환 + 오타·음수 등에 즉시 이해 가능한 오류 메시지 |
| Input | 터미널 한 줄 (`단위:값`). 오타: `meter 9.1`, `meter:`, `:2.5`, `feet:abc`, `meter:-1` |
| Output | 정상 변환 결과 / 오류 시 원인 드러나는 메시지 (묵살 종료 금지) |

### 성공 기준

| ID | 기준 | 증거 |
|----|------|------|
| SC-1 | 콜론 누락·공백 시 명확한 오류 메시지 (조용히 뻗지 않음) | 증거 1 |
| SC-2 | 메시지만으로 몇 초 안에 원인 특정 (소스·엑셀 대조 불필요) | 증거 2 |
| SC-3 | 정상·오류 케이스 TC 자동 검증 (메모장 검사 대체) | 증거 3 |

### 표면 문제 (워크북 범위 제외)

- 화려한 GUI
- 외부 JSON/YAML 설정
- 동적 단위 등록·JSON/CSV 출력
- 대규모 아키텍처 도입
- 배치 입력·중간 저장

### 8계층 (STEP 1 워크북)

- **Rule:** OCP/SRP, 묵살 종료 금지, 비즈니스 비율 고정, TC 필수
- **Command:** 구조 분석 → 검증 분리 → 리팩토링 → TC → Review
- **Skill:** 파싱·예외·pytest·Mom Test 추적
- **Test/Review Loop:** SC-1~3 기반 정상·오류 TC + Mom Test 체크리스트

전체 PRD: [docs/PRD.md](../docs/PRD.md)
